# 🚗 Car Rental & Vehicle Fleet Management API

A production-ready **Car Rental & Vehicle Fleet Management Backend API** built using **Node.js**, **Express.js**, and **Supabase (PostgreSQL & Auth)**. Features strict date-collision prevention to eliminate vehicle double-booking, dynamic server-side rental cost computation, relational joins for vehicle booking histories, vehicle fleet status lifecycle transitions, and secure Supabase JWT route guards.

---

## 🌟 Key Features & Architectural Highlights

1. **Relational Database with Constraints**:
   - PostgreSQL schema running on Supabase with Foreign Key relationships, `CHECK` constraints on vehicle categories (`Sedan`, `SUV`, `Luxury`, `Hatchback`, `Electric`), daily rates (`> 0`), fleet statuses (`available`, `rented`, `maintenance`), and rental statuses (`booked`, `active`, `completed`, `cancelled`).
   - `valid_date_range` constraint enforcing `end_date >= start_date`.

2. **Date Collision Prevention Algorithm**:
   - Query-level validation ensuring that no vehicle is double-booked:
     $$\text{existing.start\_date} \le \text{new.end\_date} \quad \text{AND} \quad \text{existing.end\_date} \ge \text{new.start\_date}$$
   - Any overlapping attempt for status in `['booked', 'active']` immediately yields `400 Bad Request: Vehicle already reserved during this timeframe`.

3. **Server-Side Dynamic Billing Calculation**:
   - Accurate calculation of total rental cost based on day spans:
     $$\text{total\_cost} = (\text{end\_date} - \text{start\_date in days}) \times \text{vehicles.daily\_rate}$$
   - Client-submitted totals are never trusted.

4. **Fleet State Machine**:
   - Automatic status transitions: `available` ➔ `rented` on booking / activation ➔ `available` on rental completion (`/complete`) or cancellation.
   - Deletion guard: Restricts deletion of vehicles with active or booked reservations with `400 Has Active Bookings`.

5. **Supabase Auth & JWT Guards**:
   - Token-based route protection using `supabase.auth.getUser(token)` to verify Bearer JWTs and extract `req.user.id`.

6. **Centralized Error Handling**:
   - All errors pass through Express error-handling middleware (`middleware/errorHandler.js`) returning standardized JSON payloads.

## 🗄️ Database Schema & SQL Migration

Run the following SQL in your **Supabase Dashboard ➔ SQL Editor**:

```sql
-- 1. Vehicles Table
CREATE TABLE vehicles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    brand TEXT NOT NULL,
    model TEXT NOT NULL,
    year INT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
    daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
    fuel_type TEXT NOT NULL,
    seating_capacity INT NOT NULL DEFAULT 5,
    status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Rentals / Bookings Table
CREATE TABLE rentals (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL, -- references Supabase auth.users
    vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
    customer_name TEXT NOT NULL,
    customer_email TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    total_cost NUMERIC(10, 2) NOT NULL,
    status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);
```

## 🚀 Getting Started Locally

### 1. Prerequisites
- **Node.js** (v18+ recommended)
- **npm** (v9+)
- A **Supabase Account & Project** ([supabase.com](https://supabase.com))

### 2. Installation
Navigate to the project folder and install dependencies:

```bash
cd Desktop/assignment-10-car-rental-system-api/Aryaa_Bhadane
npm install
```

### 3. Environment Configuration
Create a `.env` file from `.env.example`:

```bash
cp .env.example .env
```

Update `.env` with your Supabase credentials from **Supabase Dashboard ➔ Project Settings ➔ API**:

```env
PORT=5000
SUPABASE_URL=https://xxxxxxxxxxxxxxxxxxxx.supabase.co
SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

### 4. Running the Server

- **Development Mode (with live reload):**
  ```bash
  npm run dev
  ```

- **Production Mode:**
  ```bash
  npm start
  ```

Server will run on `http://localhost:5000`.

## 📋 API Endpoints Reference

### 🔐 1. Authentication (`/api/auth`)

| Method | Endpoint | Access | Description | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/auth/register` | Public | Register customer with Supabase Auth | `201 Created`<br>`400 Bad Request` |
| `POST` | `/api/auth/login` | Public | Authenticate & receive Supabase JWT token | `200 OK`<br>`401 Unauthorized` |

#### Request Example (`POST /api/auth/register`):
```json
{
  "email": "driver@travel.com",
  "password": "mypassword123",
  "name": "David"
}
```

---

### 🚗 2. Vehicle Fleet Management (`/api/vehicles`)

| Method | Endpoint | Access | Description | Status Codes |
|---|---|---|---|---|
| `GET` | `/api/vehicles` | Public | Get all vehicles (supports `?category=SUV&status=available&brand=Tesla`) | `200 OK` |
| `GET` | `/api/vehicles/:id` | Public | Get vehicle details with past rental records | `200 OK`<br>`404 Not Found` |
| `POST` | `/api/vehicles` | **Protected** | Add new vehicle to fleet | `201 Created`<br>`400 Bad Request` |
| `PUT` | `/api/vehicles/:id` | **Protected** | Update vehicle daily rate or status | `200 OK`<br>`404 Not Found` |
| `DELETE`| `/api/vehicles/:id` | **Protected** | Delete vehicle (fails if active bookings exist) | `200 OK`<br>`400 Has Active Bookings` |

#### Request Example (`POST /api/vehicles`):
```json
{
  "brand": "Tesla",
  "model": "Model 3",
  "year": 2024,
  "category": "Electric",
  "daily_rate": 4500,
  "fuel_type": "EV",
  "seating_capacity": 5
}
```

---

### 📅 3. Rental & Booking Operations (`/api/rentals`)

| Method | Endpoint | Access | Description | Status Codes |
|---|---|---|---|---|
| `POST` | `/api/rentals` | **Protected** | Book vehicle (Date overlap check + cost computation) | `201 Created`<br>`400 Collision/Error` |
| `GET` | `/api/rentals/my-bookings` | **Protected** | List rentals for authenticated customer | `200 OK` |
| `PATCH`| `/api/rentals/:id/cancel` | **Protected** | Cancel upcoming rental | `200 OK`<br>`400 Cannot Cancel` |
| `PATCH`| `/api/rentals/:id/complete`| **Protected** | Mark rental completed & return car to available | `200 OK`<br>`400 Error` |

#### Request Example (`POST /api/rentals`):
```json
{
  "vehicle_id": 1,
  "start_date": "2026-05-01",
  "end_date": "2026-05-05",
  "customer_name": "David",
  "customer_email": "david@test.com"
}
```

#### Collision Response Example:
```json
{
  "success": false,
  "error": "Vehicle already reserved during this timeframe",
  "conflicting_bookings": [
    {
      "id": 1,
      "vehicle_id": 1,
      "start_date": "2026-05-01",
      "end_date": "2026-05-05",
      "status": "booked"
    }
  ]
}
```

   - **3. Rental & Booking Operations**: `Book Vehicle #1`, `Book Collision Test (Expect 400)`, `Get My Bookings`, `Cancel Upcoming Rental`, `Complete Rental`.
4. Run the requests sequentially to verify full API functionality and collision detection.
