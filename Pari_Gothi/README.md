# 🚗 Car Rental & Vehicle Fleet Management API

A production-ready **Car Rental & Vehicle Fleet Management RESTful API** built with **Node.js**, **Express.js**, and **Supabase (PostgreSQL Cloud DB & Auth)**.

This API provides vehicle fleet inventory management, Supabase JWT authentication, server-side rental billing calculations, vehicle availability state transitions, and date-range collision prevention algorithms.

## 🌟 Features

- **Relational PostgreSQL Database**: Managed on Supabase with foreign keys, `CHECK` constraints, and automatic timestamps.
- **Supabase Authentication**: Secure user registration and login issuing JWT access tokens.
- **Bearer Token Route Guard**: Custom Express middleware validating tokens with `supabase.auth.getUser()`.
- **Fleet Inventory & Filters**: Full vehicle CRUD with category (`Sedan`, `SUV`, `Luxury`, `Hatchback`, `Electric`) and status (`available`, `rented`, `maintenance`) query filters.
- **Vehicle Reservation History**: Fetch vehicle details along with historical rental records.
- **Inclusive Date-Range Collision Prevention**: Enforces strict overlap checks `(new.start_date <= existing.end_date) AND (new.end_date >= existing.start_date)` against `booked` and `active` rentals.
- **Server-Side Billing Calculation**: Automatically computes `total_cost = (end_date - start_date in days) * daily_rate` on the server.
- **Vehicle State Machine**: Seamless transitions between `available` ➔ `rented` ➔ `maintenance`, returning to `available` upon rental completion.
- **Booking Cancellation**: Guards cancellation to only allow upcoming, uncompleted bookings.
- **Centralized Error Handling**: Uniform JSON error responses across all API endpoints.

## 🗄️ Database Setup (Supabase)

1. Sign in to your account at [supabase.com](https://supabase.com/).
2. Create a new project (e.g. `car-rental-api`).
3. Open the **SQL Editor** from the left navigation bar in Supabase.
4. Paste and execute the SQL migration script from `supabase/schema.sql`:

```sql
-- 1. Vehicles Table
CREATE TABLE IF NOT EXISTS vehicles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    brand TEXT NOT NULL,
    model TEXT NOT NULL,
    year INT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
    daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
    fuel_type TEXT NOT NULL,
    seating_capacity INT NOT NULL DEFAULT 5,
    status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Rentals / Bookings Table
CREATE TABLE IF NOT EXISTS rentals (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL, -- references Supabase auth.users
    vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
    customer_name TEXT NOT NULL,
    customer_email TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    total_cost NUMERIC(10, 2) NOT NULL,
    status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);
```

5. Go to **Project Settings** ➔ **API** and copy:
   - **Project URL** (`SUPABASE_URL`)
   - **Project API Keys** ➔ `anon` `public` key (`SUPABASE_ANON_KEY`)

## 📋 API Endpoint Reference

### 🔐 Authentication (`/api/auth`)

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|:---:|---|---|
| `POST` | `/api/auth/register` | No | Register customer with Supabase Auth | `201 Created`<br>`400 Bad Request` |
| `POST` | `/api/auth/login` | No | Authenticate and receive JWT Bearer token | `200 OK`<br>`401 Unauthorized` |

#### Request Body Example (Register/Login):
```json
{
  "name": "David Driver",
  "email": "driver@travel.com",
  "password": "mypassword123"
}
```

---

### 🚗 Vehicle Fleet Management (`/api/vehicles`)

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|:---:|---|---|
| `GET` | `/api/vehicles` | No | List all vehicles (supports `?category=SUV&status=available`) | `200 OK` |
| `GET` | `/api/vehicles/:id` | No | Get vehicle details with past rental records | `200 OK`<br>`404 Not Found` |
| `POST` | `/api/vehicles` | **Yes** | Add new vehicle to fleet | `201 Created`<br>`400 Bad Request` |
| `PUT` | `/api/vehicles/:id` | **Yes** | Update vehicle daily rate or status | `200 OK`<br>`404 Not Found` |
| `DELETE` | `/api/vehicles/:id` | **Yes** | Delete vehicle (blocks if active bookings exist) | `200 OK`<br>`400 Bad Request` |

#### Vehicle Body Example (POST):
```json
{
  "brand": "Tesla",
  "model": "Model 3",
  "year": 2024,
  "category": "Electric",
  "daily_rate": 4500.00,
  "fuel_type": "EV",
  "seating_capacity": 5,
  "status": "available"
}
```

---

### 📅 Rental & Booking Operations (`/api/rentals`)

| Method | Endpoint | Auth | Description | Status Codes |
|---|---|:---:|---|---|
| `POST` | `/api/rentals` | **Yes** | Book vehicle (validates collision & computes server-side cost) | `201 Created`<br>`400 Bad Request` |
| `GET` | `/api/rentals/my-bookings` | **Yes** | List all rentals for logged-in user | `200 OK` |
| `PATCH` | `/api/rentals/:id/cancel` | **Yes** | Cancel upcoming rental & reset car to available | `200 OK`<br>`400 Bad Request` |
| `PATCH` | `/api/rentals/:id/complete`| **Yes** | Complete rental & reset car to available | `200 OK`<br>`400 Bad Request` |

#### Rental Body Example (POST):
```json
{
  "vehicle_id": 1,
  "start_date": "2026-05-01",
  "end_date": "2026-05-05",
  "customer_name": "David Driver",
  "customer_email": "driver@travel.com"
}
```

## 🧪 Testing Flow Walkthrough

1. **Register & Login**
   - Call `POST /api/auth/register` and `POST /api/auth/login`.
   - Copy the returned `access_token` into the `Authorization: Bearer <access_token>` header.
2. **Add Fleet Vehicles**
   - Call `POST /api/vehicles` or run the sample `INSERT` from `schema.sql`.
3. **Successful Booking**
   - Call `POST /api/rentals` with `vehicle_id: 1`, `start_date: "2026-05-01"`, `end_date: "2026-05-05"`.
   - **Response**: `201 Created` with calculated `total_cost` (`4 days * 4500 = 18000.00`).
4. **Date Conflict Collision Test**
   - Call `POST /api/rentals` with `vehicle_id: 1`, `start_date: "2026-05-03"`, `end_date: "2026-05-07"`.
   - **Response**: `400 Bad Request`
   ```json
   {
     "error": "Vehicle already reserved during this timeframe."
   }
   ```
5. **Complete / Cancel Flow**
   - Call `PATCH /api/rentals/1/complete` ➔ Vehicle status automatically flips back to `available`.

## ☁️ Deployment Guide (Render)

### 1. Push to GitHub
```bash
git add .
git commit -m "feat: complete Car Rental API with Supabase and Express"
git push origin main
```

### 2. Create Web Service on Render
1. Go to [render.com](https://render.com/) and click **New + ➔ Web Service**.
2. Connect your GitHub repository (`itm-assignment-10-car-rental-api`).
3. Set the configuration:
   - **Name**: `car-rental-api`
   - **Runtime**: `Node`
   - **Build Command**: `npm install`
   - **Start Command**: `npm start`
   - **Instance Type**: `Free`

### 3. Set Environment Variables
In the Render Web Service settings ➔ **Environment**, add:
- `SUPABASE_URL`: `https://your-project-id.supabase.co`
- `SUPABASE_ANON_KEY`: `your-supabase-anon-public-key`

*(Note: `PORT` is automatically injected by Render).*

### 4. Verify Deployment
Once deployed, verify by hitting the root endpoint:
```bash
curl https://your-app-name.onrender.com/
```
