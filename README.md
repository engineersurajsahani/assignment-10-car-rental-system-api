## 📌 Executive Summary

A production-ready **Car Rental & Vehicle Fleet Management REST API** backed by **Supabase PostgreSQL** and **Supabase Authentication**. This system handles:

1. **Date Collision Prevention Algorithm:** Robust interval overlap detection preventing double bookings for any vehicle in the fleet.
2. **Automated Dynamic Cost Billing:** Server-side calculation multiplying exact rental duration spans by daily vehicle rates.
3. **Fleet State Transition Management:** Dynamic vehicle availability states (`available` ➔ `rented` ➔ `maintenance`).
4. **Relational PostgreSQL Modeling:** Foreign key constraints (`ON DELETE RESTRICT`), data integrity checks, and nested joins between vehicles and reservation histories.
5. **Secure Token Verification:** Route guards validating Supabase JWT access tokens passed via `Bearer` authorization headers.
6. **Dual Mode Architecture:** Seamlessly connects to live Supabase Cloud when configured, with a built-in mock simulator enabling offline development and instant automated test runs without external blockers.

## 🗄️ Database Schema & Relational Design

The database schema is defined in [`schema.sql`](./schema.sql). Execute this directly in the **Supabase SQL Editor**:

### 1. Vehicles Table
```sql
CREATE TABLE vehicles (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    brand TEXT NOT NULL,
    model TEXT NOT NULL,
    year INT NOT NULL,
    category TEXT NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
    daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
    fuel_type TEXT NOT NULL,
    seating_capacity INT NOT NULL DEFAULT 5,
    status TEXT NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);
```

### 2. Rentals Table
```sql
CREATE TABLE rentals (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id UUID NOT NULL, -- references Supabase auth.users(id)
    vehicle_id BIGINT REFERENCES vehicles(id) ON DELETE RESTRICT,
    customer_name TEXT NOT NULL,
    customer_email TEXT NOT NULL,
    start_date DATE NOT NULL,
    end_date DATE NOT NULL,
    total_cost NUMERIC(10, 2) NOT NULL,
    status TEXT NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    CONSTRAINT valid_date_range CHECK (end_date >= start_date)
);
```

### Relational Constraints & Indexes
- **`ON DELETE RESTRICT`**: Prevents deletion of vehicles that have historical or active rental records.
- **`CHECK (end_date >= start_date)`**: Database-level constraint guaranteeing valid chronological booking windows.
- **Indexes**: Fast indexed lookups on `rentals(vehicle_id)`, `rentals(user_id)`, `rentals(start_date, end_date)`, and `vehicles(status, category)`.

## 🛡️ Date Collision Prevention Algorithm

Double booking is mathematically prevented by querying all overlapping active bookings before finalizing a reservation:

$$\text{Collision Condition:} \quad (\text{existing}.\text{start\_date} \le \text{new\_end}) \quad \text{AND} \quad (\text{existing}.\text{end\_date} \ge \text{new\_start})$$

```javascript
// Supabase query implementation
const { data: overlappingBookings } = await supabase
  .from('rentals')
  .select('id, start_date, end_date, status')
  .eq('vehicle_id', vehicle_id)
  .in('status', ['booked', 'active'])
  .lte('start_date', end_date)
  .gte('end_date', start_date);

if (overlappingBookings && overlappingBookings.length > 0) {
  return res.status(400).json({
    success: false,
    message: 'Vehicle already reserved during this timeframe.',
    conflict: overlappingBookings[0]
  });
}
```

Cancelled (`status = 'cancelled'`) and completed (`status = 'completed'`) rentals are excluded from the collision check, freeing up the dates automatically.

## 💰 Automated Day Count & Dynamic Billing Computation

Rental pricing is computed dynamically on the server:

```javascript
const calculateRentalDays = (startDateStr, endDateStr) => {
  const start = new Date(startDateStr);
  const end = new Date(endDateStr);
  const diffTime = end.getTime() - start.getTime();
  const diffDays = Math.ceil(diffTime / (1000 * 60 * 60 * 24));
  return Math.max(1, diffDays); // Minimum 1-day rental
};

const days = calculateRentalDays(start_date, end_date);
const total_cost = Number((days * Number(vehicle.daily_rate)).toFixed(2));
```

### Example:
- **Vehicle #1 (Tesla Model 3):** `daily_rate = ₹4,500`
- **Rental Period:** `2026-05-01` to `2026-05-05` (4 days)
- **Calculation:** $4 \times ₹4,500 = ₹18,000$
